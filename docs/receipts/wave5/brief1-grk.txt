TASK: Design pixel-art IDLE ANIMATIONS for 4 Space Station 14 object/structure sprites (32x32 RSI states, single direction each, all currently static single-frame). Implemented as programmatic per-pixel edits — you design, you do NOT draw. Each sprite's one-line note tells you its role; lean into it.

NOTE ON GROUPED PALETTE LETTERS: one sprite below (lantern_on) has more distinct colors than fit a single-letter-per-color map, so some letters represent a small GROUP of very close (not identical) shades — marked "[n shades]" in the palette listing. Treat a grouped letter as ONE region exactly like any other letter; you don't need to pick a specific shade, the executor keeps every pixel's own exact original color when it applies your ops.

IMPORTANT — RUNTIME TINTING: some of these sprites are stored as flat GRAYSCALE (every opaque pixel has R=G=B) or otherwise reused across multiple entities with DIFFERENT color treatments, because the game re-colors them per-instance at runtime. Any sprite marked "TINTED PER-INSTANCE" in its note below MUST use ONLY these op kinds so the animation still looks correct under ANY runtime tint (including NO tint at all): `brightness` (factor > 1 brightens, < 1 darkens — this is what should carry almost all of your glint/sparkle/pulse effects here), `alpha`, and `lerp` ONLY with `to:[255,255,255]` (toward white) or `to:[0,0,0]` (toward black). Do NOT use `hue_shift` or `lerp` toward any other color on a "TINTED PER-INSTANCE" sprite — it would look wrong once the game applies (or doesn't apply) its own tint. Sprites marked "fixed color, no runtime tint" have no such restriction — hue_shift and colored lerps are fine there if the concept calls for it.

HARD CONSTRAINTS:
- Frame 0 = the original sprite, byte-identical. 2-4 frames, looping.
- Masks expressed EXACTLY as: (a) palette letters from the map, optionally bounded by rect region [x0,y0,x1,y1] inclusive; (b) explicit pixel lists.
- Allowed ops per frame: brightness multiply (factor), alpha set (value 0-255), px_off {at:[x,y]}, px_copy {from:[x,y],to:[x,y]}, lerp toward rgb {to:[r,g,b], t:0..1}, hue_shift {degrees: -180..180} (rotates hue of masked pixels, keeps saturation/value) — but see the RUNTIME TINTING rule above for which ops are allowed on which sprite.
- Silhouette stays stable except single-pixel sparkle toggles. Untouched pixels byte-identical.
- Delays: twinkles/glints 0.1-0.25s, pulses/breathes 0.3-0.6s. Loop <= ~2.5s. Vary rhythm (a long hold then quick frames reads better than uniform).
- Every mask you write MUST reference letters/coords that actually exist in the map — do not invent coordinates or features not present in the pixel map.
