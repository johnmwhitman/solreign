## Real signal: RGA schema validator would fail on real content, independent of billing

The validator (`RobustToolbox/Schemas/rga.yml` via `PaulRitter/yaml-schema-validator`)
requires every attribution's `source` field to be a URL (or literal `"NA"`) and every
`license` field to exactly match one of a fixed enum
(`CC-BY-4.0`, `MIT`, `Custom`, etc.). I reimplemented the same schema+validators
locally with `yamale` (the underlying library the action wraps) and ran it against all
88 `attributions.yml` files under `Resources/`. **8 files fail:**

- `Resources/Textures/_Solreign/attributions.yml` (11 entries)
- `Resources/Textures/_Solreign/Parallaxes/attributions.yml` (9 entries)
- `Resources/Textures/Tiles/attributions.yml` (1 entry)
- `Resources/Textures/Tiles/Planet/Concrete/attributions.yml` (1 entry)
- `Resources/Textures/Parallaxes/attributions.yml` (1 entry)
- `Resources/Audio/_Solreign/attributions.yml` (14 entries)
- `Resources/Audio/Effects/attributions.yml` (1 entry)
- `Resources/Audio/Effects/Weather/attributions.yml` (2 entries)

Two distinct shape problems:
1. **`source` must be a URL or `"NA"`**, but the Solreign-authored in-house-generation
   entries use descriptive provenance prose instead (e.g. `"In-house generation,
   2026-07-11. See assets/sprites-batch1/PROVENANCE.md. Wired: ..."`). The schema was
   built for the upstream model (external commercial asset → attribution URL); it was
   never adapted for this fork's in-house-generation + provenance-doc convention.
2. **`license` must exactly match the enum**, but two entries (`Resources/Audio/Effects/`
   and `Resources/Audio/Effects/Weather/`) use a descriptive sentence
   ("Sonniss GDC Bundle License (commercial use permitted, no attribution required;
   ...). Verified 2026-07-16 via https://sonniss.com/gdc-bundle-license/.") instead of
   a bare enum value — likely `Custom` was intended but the field was left as prose.

This is **not** a duplicate of the existing CC-BY-NC license-content sweep
(`docs/CCBYNC-INVENTORY-2026-07-12.md`, `LICENSE-BATCH-*` receipts) — those check
*whether* NC-licensed assets exist; this is a pure **schema-shape** violation on
otherwise-fine, non-NC, in-house-generated assets. It has never been caught because CI
has been billing-locked continuously since before Wave 22 (RGA schema validator itself
predates the fork's Solreign content but this specific violating content was added over
2026-07-11 through 2026-07-17, i.e. entirely during the billing outage).

**Not fixed in this lane** per scope (content fixes belong to their own lane, not
CI-triage). Two real options for that lane: (a) extend `rga_validators.py`'s `source`
validator to also accept a `"See <path>"` provenance-doc pattern for in-house assets, or
(b) reformat the 8 files' `source`/`license` fields to the schema's existing contract.
Recommend (a) — the in-house-generation convention is now the norm for this fork's own
art pipeline, not a one-off.

## Why the heavy checks (Build & Test Debug, Map Renderer, YAML Linter, Test Packaging) were left alone

The task brief allows disabling workflows that "duplicate our local battery AND can't
run usefully in CI." These four do duplicate the local battery, but the project's own
prior audit (`docs/AUDIT-2026-07-12.md`, `docs/ROADMAP-PHASE3.md` line 32) explicitly
argues the opposite of disabling them: *"Green CI / 'tests pass' — that CI ran at all —
CI billing (S4) must be unblocked; a claim of green requires a completed run ID, not a
belief."* That audit caught a real false-confidence case (`AllItemsHaveSpritesTest`
claimed "known failing upstream" with no evidence) precisely because CI had gone dark
and only local claims remained unchecked. Disabling the independent CI test run here
would work against the project's own stated definition-of-done. Recommend leaving them
wired and letting J3 (billing) be the actual fix.

## New consolidated workflow: `solreign-ci-content-checks.yml`

Per the brief's option to add "a single consolidated Solreign CI workflow... IF cheap
and runners can handle it — recommend the shape, implement the light version": the four
genuinely light/bounded checks (RSI Validator, RGA schema validator, Map file schema
validator, Solreign orphan-reachability scanner) are now one workflow file with four
parallel jobs, replacing four separate workflow files. Same per-check runtime cost
(nothing got heavier), but pushes now produce **one** workflow-run notification for
these checks instead of four. `YAML Linter` was considered for this bundle (the name
suggests "light") but excluded — it requires a full `dotnet build --configuration
Release` of the whole content tree, the same weight class as Build & Test Debug, so
bundling it would have made the "light" workflow heavy.

Recommended shape if John wants to go further later: fold `YAML Linter` into a second,
separate "heavy checks" bundle alongside Build & Test Debug (both already build the full
tree; sharing one `dotnet build` step between them via job-level `needs`/artifact reuse
would cut real runner-minutes, not just notification count) — flagged as a follow-up
idea, not implemented here since it touches the test-running heavy path the audit doc
explicitly wants left alone/independent.
