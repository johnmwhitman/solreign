  same shape as `Content.Server`/`Content.Client`'s existing files. Needed for the test-only

**Production edits (all within the W1 file boundary):**
- `SolreignFxCueV1.cs` — added an `internal` constructor overload that lets `SchemaVersion` vary
  (no other constructor path in the codebase can do this — the field initializer burns in
  `CurrentSchemaVersion` for every other path). Models what a hostile/buggy server's raw
  deserialized bytes could actually produce (`[NetSerializable]` types are populated by the

  `InternalsVisibleTo`; production assemblies never get it.

  replaced with `TryResolveEntityWorldPosition` (entity anchors now get the same
  finiteness/±16384-ceiling scrutiny coordinates already had); `TryClampNumericField`/
  `IsWithinLocalBounds` now take hardcoded wire-ceiling params and hard-reject
  (new `MalformedPrototypeBounds` reason) if the resolved prototype's own bounds are non-finite,
  inverted, or outside the ceiling — checked before ever comparing the wire value against them.
- `SolreignFxCuePrototype.cs` — added `MinScaleFloor` (0.01) + a load-time validation rule,
  mirroring the existing `MinDurationFloor`, closing the gap between spec §1.5's open-interval
  `(0, 8]` scale ceiling and the prior closed-zero `WireScaleMin = 0f`. Also simplified
  `[Prototype("solreignFxCue")]` to bare `[Prototype]` (redundant explicit id matched the
  autogenerated value — analyzer warning RA0042, fixed to match the repo-wide convention of 130
  bare `[Prototype]` attributes vs. 11 explicit ones).

## 4. grk adversarial review — two rounds

**Round 1** (full W1 diff, 2,836 lines): 2 High, 4 Medium, 1 Low finding. Disposition:

| # | Finding | Disposition |
|---|---|---|
| H1 | `DetailOnly` audience classification never checked in `TryValidateReceived` | **Not fixable at this layer, by design** — confirmed with grk in round 2. Delivery scope (broadcast vs. session-targeted) is determined by the network event's delivery mechanism, not carried in the `NetSerializable` payload; the receiving client cannot tell from a cue's fields whether it was supposed to be the only recipient. Per spec §5.2 this stays an API-enforced discipline in W2's `RaiseCue`/`RaiseSecretRoleCue` split. Tracked as W2's obligation, not W1 debt. |
| H2 | Entity anchors skipped the world-ceiling/finiteness check coordinates got (only confirmed existence) | **Fixed.** `ISolreignFxAnchorResolver.EntityAnchorExists` → `TryResolveEntityWorldPosition`; both `TryCreate` and `TryValidateReceived` now require the resolved position finite AND within ±16384. Mutation-checked (disabled the ceiling check, confirmed the corresponding test failed, reverted). |
| M3 | Wire ceilings not dual-enforced on the receive path; a NaN/inverted local prototype bound makes every comparison-based check silently pass | **Fixed.** New `MalformedPrototypeBounds` reason; both `TryClampNumericField` (server) and `IsWithinLocalBounds` (client) now hard-reject a non-finite/inverted/out-of-ceiling prototype bound before comparing the wire value against it. |
| M4 | Scale's spec ceiling is the open interval `(0, 8]`; code only enforced closed-zero `[0, 8]`, no floor analogous to duration's | **Fixed.** Added `MinScaleFloor = 0.01f` + a load-time validation rule mirroring `MinDurationFloor`. |
| M5 | Palette/phase fallback under a `count ≤ 0` prototype can mint a meaningless index (no throw, but not "safe to index") | **Deferred, by design** — spec explicitly forbids rejecting on palette/phase (substitution only); the correct fix is keeping a malformed prototype out of the allowlist at load time, which is W2/W3's job to wire (the validation rule set already exists in `SolreignFxCuePrototypeValidation`). Confirmed with grk in round 2. |
| Low | New `Content.Shared/AssemblyInfo.cs` opens all `internal` members to `Content.Tests`/`Content.IntegrationTests`, not just the one constructor | **Accepted, documented.** Same blast radius as the pre-existing `Content.Server`/`Content.Client` `AssemblyInfo.cs` files — established repo convention, not a deviation. Comment added explaining scope. |

**Round 2** (fix-round diff + rationale for H1/M5 dispositions): **grk verdict — "sound, ship the
fix round."** Confirmed H2/M3/M4 land correctly, no new High/Medium introduced, agreed with both
the H1 (structural, not fixable at the validator layer) and M5 (spec forbids reject-on-palette,
correct fix is the load-time hook) dispositions. Two residual notes, both accepted as fine for W1
and NOT actioned this round: (a) `MinScaleFloor` is currently load-time-only, not runtime
dual-enforced the way wire ceilings are — optional future tightening, same shape as the
pre-existing duration floor; (b) reusing `AnchorCoordinatesOutOfCeiling` as the failure reason for
an out-of-ceiling ENTITY anchor (not just coordinates) is a naming smell, not a bug.

## 6. Justified deviations from a literal reading of the spec

1. **`ISolreignFxCueRaiser.cs` and `SolreignFxTokenBucket.cs` exist in W1** even though the spec's
   §8 file-boundary table assigns their real implementations to W2. Both are pure
   contracts/scaffolding with zero call sites — the mission's own compressed restatement of W1
   scope explicitly asked for "PVS/actor-excluding raise API split (no raw broadcast)" and "budget
   scaffolding interfaces (no consumers)," which these two files are. Not implementation creep.
2. **`SolreignFxProfileGate.cs` lives in `Content.Shared`**, not `Content.Client` as spec §8's W2
   file boundary literally names it. The spec's own W1 boundary requires
   `SolreignFxProfileGateTests.cs` to exist NOW, and W1's file boundary authorizes no
   `Content.Client` file — so the only legal home for testable-in-W1 gate logic is `Content.Shared`,
   mirroring the same engine-decoupled-pure-logic pattern the spec itself uses for
   `TryValidateReceived`'s injected resolver interfaces. W2 is expected to wrap this in a real
   `Content.Client` system (CVar subscription, `RefreshActive`-style reconciliation on profile
   change) — this file is the math half only, same split as the codebase's own
   `MovementBobMath.cs`/`MovementBobSystem.cs` precedent (except that precedent keeps both halves
   in `Content.Client`, which W1's own file boundary doesn't authorize touching).
3. **Two additional test files beyond the four spec names** (`SolreignFxSeedMixingTests.cs`,
   `SolreignFxTokenBucketTests.cs`) — the mission explicitly named "seed determinism" as a required
   test, and the token bucket's own shipped docstring already claimed "already-tested," which
   wasn't true until this session. Both are tests of already-in-scope W1 files, not new production
   surface.

No other deviations. Every other file, method, and test maps directly onto an explicit line item
in the spec or the mission's restatement of it.
