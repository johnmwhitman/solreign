## 2. `circuitprinter.ogg` duplicate CC0/CC-BY-NC-4.0 entries — SKIPPED (shopping list's premise was wrong)

**The shopping list's claim:** the attributions.yml has "contradictory" CC0 + CC-BY-NC-4.0 entries for the same file; the CC0 one (OroborosNZ, freesound 273649) is "the" true source and the NC one is a copy-paste artifact to be deleted.

**My re-verification found this is false.** This repo's `Resources/Audio/Machines/attributions.yml` was mechanically converted from a `license.txt` file in upstream SS14 PR #21586 ("convert license.txt to attributions.yml in Machines"). The original `license.txt` line, straight from that PR's diff, reads:

```
circuitprinter.ogg taken from https://freesound.org/people/OroborosNZ/sounds/273649/
  and https://freesound.org/people/170048@virtualwindow.co.za/sounds/408041/ and edited
```

This is not a duplicate/contradiction — it explicitly documents that `circuitprinter.ogg` is a **composite/edit combining both sources**. The CC0 source and the CC-BY-NC-4.0 source are both genuine ingredients of the shipped file. (Confirmed the same two-entry "duplicate" exists verbatim in upstream `space-wizards/space-station-14` today too — this is an upstream-wide characteristic of the file, not a Solreign-introduced bug.)

Additional evidence considered (both freesound pages fetched and read):
- CC0 source (273649): "Weight machine, gas resistance" by OroborosNZ, 95.5s, stereo 96kHz/16-bit, tags `factory, gas, gym, hydraulic, industrial, machine, machinery, weight`.
- CC-BY-NC-4.0 source (408041): "Key Cutting Machine.wav" by 170048@virtualwindow.co.za, 11.7s, stereo 48kHz/24-bit, tags `Hum, Machine, Cut, Cutting, Grind, Grinding, High, Industrial, Key, Motor, Pitch, Power`.
- The in-repo file is 4.0s, mono, 44.1kHz — a plausible crop-and-downmix of either or both.

Since the license.txt origin explicitly states both were used to build the final edited file, deleting the NC line would be removing a genuinely-required attribution for material actually present in the shipped audio — not a documentation fix. `circuitprinter.ogg` is legitimately NC-encumbered as-is; a real fix would require re-sourcing/re-editing the sound from clean-only material, which is a download/edit job, out of this wave's zero-download scope.

**Verdict: SKIPPED, reported. No attributions.yml or audio change made for this file.**

The shopping list described this as "5 files" needing a YAML-only repoint. Independent verification found the actual blast radius is much larger, but confined entirely to **collection definitions**, never individual consumers:


Every one of those ~200 consumer lines references the sound **by collection id** (`collection: MetalBreak`, etc.), never by direct file path. Per-file grep for each individual candidate NC filename (`metal_crunch.ogg`, `metal_break1-5.ogg`, `metal_glass_break1-2.ogg`, `metal_slam5.ogg`) across the **entire repo** (not just Prototypes — also `Content.Server/Client/Shared`, `Resources/Locale`) turned up hits in exactly two files:

**Conclusion:** the correct fix is to repoint the `files:` lists of the collection *definitions* in `destruction.yml`/`traits.yml` to already-clean, same-repo audio — zero consumer prototypes need to be touched, because none of them reference the underlying files directly.
